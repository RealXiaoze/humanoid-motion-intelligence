# X-Planner：面向具身操作的事件结构规划

[论文](https://arxiv.org/abs/2609.25187) · [官方代码与项目](https://github.com/X-Square-Robot/Xplanner)

## 规划器与动作模型的分工

长程操作策略若只把当前图像和指令映射为动作，系统内部就缺少显式的“现在做哪一步、这一步是否完成、执行是否偏离”的任务状态。X-Planner 将这部分能力做成事件结构规划前端：输入高层任务、同步多视角观察和可选执行历史，输出可读的下一事件，交由下游 World-Action 模型完成具体时空动作。它本身不是直接控制关节的完整 VLA，也不重新训练下游动作模型；事件是二者之间语义对齐的中间接口。

数据来自 Ego、UMI 和遥操作示范，按 Task、Subtask、Action、Segment 四层组织，标注深度随来源而不同：Ego/UMI 主要覆盖 L1–L3，遥操作数据可到 L0–L3，缺少 Segment 标注不代表动作不存在。训练样本将过程拆为初始计划、执行中的当前/下一事件、进度与继续状态、以及终止状态。对接管时刻标注可以监督策略何时出错；由于单一采集策略产生的失败分布有偏，团队又补充人为设计的失败情形。论文分析子集保留 1,500/1,654 条候选 episode，覆盖 167 个数据集和 30 个任务类别；这组统计不是三类来源整体训练混合的占比说明。

## 两种事件表示与训练

共享视觉语言骨干提供两种计划形式。离散事件模式输出结构化 JSON 状态，便于上层 Agent 或操作员检查、修改；潜在模式把连续 CoT 状态通过 Staircase Decoding 分布到错开的 Transformer 深度，并行推进部分推理，减少逐 token 串行生成。冻结的 latent-to-text 模块把潜在表示重构为文本，为连续表示保留语义锚点。两种模式都由下游 World-Action 模型消费，后者通过固定的 cross-attention 条件接口接收计划特征，因此规划器可以改变“任务分解怎么表示”，但不应把其结果误读为新增的底层控制能力。

训练把目标分开处理：结构化计划 JSON 使用监督微调；规划端条件特征与下游原有文本表示空间用均方误差对齐；潜在 CoT 使用冻结语言模型作重构目标，主要更新 Staircase 分支及前缀投影。固定下游模型使评测更集中于规划条件化的作用，但离线标注历史与部署时滚动模型历史并不完全一致，论文也指出这构成 oracle-context 差距。推理使用事件模式时每轮根据新观察更新下一事件；潜在模式则提供紧凑的隐式计划，不能仅凭并行层结构推断端到端时延必然更低。

## 评测证据与限制

离线两步规划比较中，X-Planner 的 BERTScore-F1 为 0.9011、Judge Overall 为 1.411，在四个模型中两项均列第二，低于 kimi3 的 0.9108 和 1.434。该分数衡量规划文本相似性和评审器给出的整体质量，不是机器人执行成功率。实机评测在双臂桌面平台上使用同步多视角观察，以 0–100 的 Task Progress 记录按任务规则完成的部分进度。推理操作套件均值为 71.60，高于 U-Scratch 的 59.50、π0.5 的 56.40、DreamZero 的 32.70 和 LingBot-VA 的 31.60；泛化套件均值为 53.75，高于该套件中最高基线 DreamZero 的 28.50。指标允许部分得分，不能把 71.60% 写成二元成功率。

论文将真实执行结果报告为完整 event-mode 系统成绩，尚不能分离失败监督、Staircase 潜在推理、事件标注和文本特征对齐各自的贡献；也未建立不同任务下的置信区间或统计显著性。复用时要先检查事件 schema、同步相机视角、历史窗口和下游 World-Action 的条件接口是否匹配，再判断是否需要重训。X-Planner 的价值是为任务规划提供可检查、可滚动更新的事件语言，不是替代底层闭环控制器。
