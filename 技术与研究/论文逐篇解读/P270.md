# GigaWorld-Policy-0.5：将未来视觉监督留在训练、动作留给部署

[技术报告](https://arxiv.org/abs/2607.13960) · [项目](https://open-gigaai.github.io/giga-world-policy/) · [代码](https://github.com/open-gigaai/giga-world-policy)

GigaWorld-Policy-0.5 是面向低延迟机器人操作的 World Action Model（WAM）。给定左、前、右三路观测、机器人本体状态和语言指令，模型在训练中联合预测动作块与该动作之后的多帧视觉状态；这让未来场景变化直接监督动作表征。实际部署时只保留动作生成路径，跳过未来视频 token 的解码，将世界动态作为训练信号而非在线视频生成负担。

## 动作中心的联合预测

三路相机画面按固定布局拼为一幅复合图像，再经 Wan 视觉 VAE 编码为潜变量。umT5 将语言指令变成条件特征，MLP 把机器人状态和动作块映射到视觉隐空间。核心是 Mixture-of-Transformers：视觉专家建模当前与未来视频 token，动作专家处理动作 token，各自使用专属交叉注意力和前馈层，再通过多模态自注意力交互。注意力掩码使动作 token 读取当前视觉、状态和语言条件，并让未来视觉 token 读取对应动作。该因果信息流建立动作预测与未来场景变化之间的对应。

动作和未来视觉潜变量分别加入噪声，并使用各自的流时间步与 shift 参数，模型共同回归两种模态的流速度。除此 WAM 目标，预训练混合 Action-Conditioned World Modeling（AC-WM）：给定观测和外部机器人动作，单独学习对应未来视觉演变，增加动作条件与动态结果间的监督。视觉专家从 GigaWorld-1 初始化，动作专家由其兼容权重拷贝并按较小维度裁剪。两阶段训练先在约 2,000 小时筛选后的开源机器人数据和内部真机数据上做机器人域预训练，再用目标机器人的观测、指令、状态和动作轨迹联合微调动作与未来视觉分支。

## MoT 部署与 AutoResearch

视觉专家隐藏维度为 3,072、FFN 维度 14,336；动作专家分别为 1,024 和 4,096，使得动作路径相对轻量。推理时动作 token 仍读取观测、语言和本体状态，模型直接解码连续动作块，不计算未来视觉潜变量。运行栈对输入视觉/语言上下文做 KV cache，结合 `torch.compile` 与 C++ 原生运行时，统一处理相机图像、张量构造、模型执行、缓存与动作后处理，支持机器人控制中间件进行闭环调用。

AutoResearch 用于自动探索动作损失与视觉动态损失共同优化时的训练配置：代理生成候选学习率和 warmup 方案，运行短程训练、收集验证集指标、筛选配置，再延长训练。水果抓取搜索使用约 3.9 小时、930 个 episode 的数据，其中 300 个用于训练、30 个留作验证；所有候选共享初始化、数据切分和优化器。1,000 步学习率试验中，`6e-5` 的评测动作 MSE 最低为 0.409764；batch 搜索保留原始 16，最终选择 30,000 步 checkpoint 做实机评测。

## PiPER 实机结果

实机使用 AgileX PiPER 六自由度机械臂和夹爪。指令跟随的每次试验按四个阶段计分：到达目标、抓取、移动至目标位置、成功放置，每阶段 0.25 分，共做 10 次后取均值。六类水果的“抓指定水果放入篮子”任务平均得分为 0.85，π0.5、Motus、FastWAM 和前代 GigaWorld-Policy 分别为 0.76、0.80、0.78、0.80；六项对象—目标位置组合的摆放任务平均为 0.89，最强对照 Motus 为 0.83。表中列出的长程任务 Food Heating 和 Tableware Arrangement 各进行 10 次，成功率均为 0.80，π0.5 平均为 0.60。

推理计时在启用 KV cache 与图编译时，A100 延迟 189 ms，低于 FastWAM 的 229 ms 和 π0.5 的 225 ms；本地 RTX 4090 为 110 ms，C++ 部署降至 85 ms。实机汇总 SR 表中 GigaWorld-Policy-0.5 为 0.85，C++ 路径相同；比较模型 π0.5、Motus、FastWAM 和 GigaWorld-Policy 分别为 0.76、0.80、0.78 和 0.80。混合 AC-WM/WAM 消融在相同下游微调配方下更快达到较高水果抓取成功率，最终达到 0.85，体现动作条件未来观测监督对动作表征迁移的帮助。
