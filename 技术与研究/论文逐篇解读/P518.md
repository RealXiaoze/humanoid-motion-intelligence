# XMimic 与 XSoma：把世界模型训练里的串行工作并行化

[论文](https://nico-bohlinger.github.io/papers/2026_xmimic_xsoma.pdf) · [代码](https://github.com/nico-bohlinger/xmimic)

这篇扩展报告沿用 SuperMimic 的模型式训练思路，解决每次迭代里许多小 GPU 操作串行执行的开销。XMimic 做动作跟踪，XSoma 做崎岖地形速度跟踪。

## 方法与流程

采样用 MuJoCo Warp，策略梯度通过学到的动力学模型传递。XMimic 将采样、模型更新、策略更新和评估分配到不同 GPU 并行。XSoma 在一张 GPU 上采样并更新世界模型，其余 GPU 并行计算策略梯度；世界模型只学习机器人动力学，足下地形高度等信息按已知地形直接计算。

两者把完整训练迭代编译为 JAX/XLA 程序，减少 Python 在每个小操作之间的调度等待；同时把不依赖想象状态的参考项和观测噪声提前计算，缩短策略更新中反向传播的串行链。仅编译并不自动消除这种依赖，因此并行化还要重新安排采样、模型拟合和策略更新。

XMimic 的不同设备可以使用前几次迭代的策略或世界模型，不必等本轮所有步骤结束；第四张 GPU 专门执行指导重置的评估。XSoma 的瓶颈更集中在策略更新，于是多个学习器从各自的起始状态同时计算梯度，再依次应用这些梯度，代价是后续更新使用略旧的策略梯度。

在地形任务中，XSoma 由想象出的关节角计算足端位置，再查询仿真地形高度；奖励和终止条件据此计算，不要求世界模型把整个地形一起预测出来。它使用约一秒的想象窗口且不使用价值网络。运动跟踪的 XMimic 则保留较短的想象窗口和价值网络，两者不能混为完全相同的训练配置。

## 评测结果

四张 H100 上，XMimic 达到 40 条 LAFAN1 片段跟踪目标用时 0.86 分钟，XSoma 达到所用 FastSAC 对照目标用时 0.77 分钟。论文计时排除启动、一次性编译和训练后的检查点评估；这两项结果均为仿真训练与评测，不是包含全部开销的真机部署时间。

论文的速度对比也要区分设备数量：上述四卡结果分别对比单卡 BlinkMimic 和单卡 FastSAC，减少的是达到目标的墙钟时间，不代表总 GPU 时间按相同倍数下降。启动和编译在缓存命中与未命中时耗时不同，实际端到端等待仍要把它们加回去。

跟踪任务的达标条件是连续三次检查点评估中，所有片段都未触发失败且归一化回报达到指定阈值；地形任务则依据线速度和偏航速度跟踪奖励连续达标。两种任务使用不同指标，因此两组不到一分钟的数字不能直接比较谁的控制能力更强。
