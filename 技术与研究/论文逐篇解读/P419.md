# LingBot-Map：面向流式三维重建的几何上下文模型

[论文](https://arxiv.org/abs/2604.14141) · [项目页](https://technology.robbyant.com/lingbot-map) · [官方代码](https://github.com/robbyant/lingbot-map)

## 因果重建中的长期漂移

从连续视频在线恢复相机位姿、深度和场景几何，必须在不读取未来帧的条件下同时控制计算量和累计漂移。纯局部窗口推理成本稳定，却容易忘记远处的起点和历史路径；全序列注意力可利用长程信息，但内存会随视频增长。LingBot-Map 把问题设计为流式三维重建：每帧输入经模型更新相机轨迹和稠密深度，可再反投影为点云。它采用前馈神经重建而非每一帧都运行传统位姿图优化，关键贡献是将不同时间尺度的几何上下文安排进受限注意力。

骨干是 DINOv2-Large，每帧图像形成视觉 token，并附相机、register 与 anchor token。Geometric Context Attention（GCA）把历史分成三部分：初始 anchor 帧为坐标系和尺度建立参照；局部 pose-reference window 提供相邻帧的稠密几何线索；trajectory memory 压缩较早轨迹信息，用来减轻长距离漂移。帧内注意力与 GCA 交替更新，专用头回归相机位姿和深度。推理状态因此不是简单保留全部历史图像，而是以锚点、局部帧和记忆 token 构成紧凑上下文；锚点数、窗口长度与记忆内容直接决定精度和内存的折衷。

## 两阶段训练与长序列执行

训练先以多视角离线基础模型学习通用几何，再将注意力替换为 GCA 并继承基础权重，训练因果流式模型。基础阶段使用多视角序列，第二阶段把训练视图数从 24 逐步增至 320，并随机改变局部参考窗口长度 16–64 帧，使模型适应不同上下文预算。训练数据混合不同多视角数据与长视频；长轨迹阶段使用 Foldback Video Sampler 组织片段。相对位姿损失约束局部运动，绝对位姿损失提供全局坐标参照，Video RoPE 则让轨迹记忆知道帧的时间顺序。论文报告基础阶段用 64 GPU 训练约两周，流式模型再进行约 160k 次迭代；推理代码支持 KV cache 分页和淘汰以限制显存。

GCA 对超出局部窗口的历史帧保留相机、anchor 与四个 register token，共 6 个 token，并丢弃完整图像 token。因此历史缓存仍随序列长度增长，只是增长速度显著降低；分页缓存减少追加和淘汰时的内存重分配开销。论文在 518×378 分辨率、64 帧局部窗口、最多 1,000 帧的设置下报告约 20 FPS，相同模型的普通 PyTorch 缓存实现约为 10.5 FPS。超过训练长度时可间隔保留历史关键帧。对于更长的城市级序列，Visual Odometry（VO）模式把视频切为重叠窗口，每窗重新初始化并因果推理，再以 Sim(3) 对齐重叠部分，以窗口化执行管理单次推理的内存。

## 基准结果与系统定位

评测包含 Oxford Spires、ETH3D、7-Scenes、Tanks and Temples、NRGBD、Sintel 与 KITTI，覆盖室内、室外、动态场景和数百至数千帧序列。Oxford Spires 从 320 帧稀疏设置扩展到完整 3,840 帧时，LingBot-Map 的报告误差从 5.37 变为 5.60，而若干流式基线随长度增长明显退化；同一评测约 20.29 FPS。动态 Sintel 与 KITTI 上报告 ATE 分别为 0.10 m 和 24.12 m；NRGBD 点云重建 F1 为 65.10，高于 Wint3R 的 56.96。论文强调这些结果来自无状态重置的单次在线流式评测，和离线双向重建或迭代优化方法的计算设定不同。

工程上它可作为机器人视频空间记忆、地图构建或后续导航模块的几何输入，但不包含完整回环检测、全局位姿图优化和导航决策。尤其在 VO 模式中，跨窗 Sim(3) 对齐是新误差源；直接输出模式则受可保持的历史范围约束。若在真实机器人上接入，还需验证相机内参、运动模糊、滚动快门、动态物体与本体振动是否符合评测分布，并把相机轨迹误差与点云质量分开评估。模型以约 20 FPS 输出几何，不能单独证明机器人获得了实时避障或可执行规划能力。
