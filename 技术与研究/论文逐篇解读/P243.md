# UniLab：解耦 CPU 仿真与 GPU 学习的机器人强化学习训练栈
[论文](https://arxiv.org/abs/2605.30313) · [项目主页](https://unilabsim.github.io/) · [代码](https://github.com/Motphys/UniLab)

## 设计目标与训练数据流

UniLab 的设计目标是提升机器人强化学习端到端训练效率，让 CPU 并行仿真、GPU 策略学习和数据运行时形成高效流水线。完整训练耗时还包括 rollout 采集、样本搬运、经验缓存、策略更新与权重同步；如果 collector 和 learner 彼此等待，单独加速某一端不一定缩短达到目标策略所需的墙钟时间。UniLab 因此将 CPU 并行仿真、GPU 策略学习和运行时调度作为一个端到端系统设计。

## 异构运行时与算法调度

使用者以任务配置定义环境中的观测、动作、奖励、终止条件、事件和课程，再选择机器人任务、物理后端和强化学习算法。CPU workers 并行推进批量刚体仿真并生成轨迹或转移数据；GPU learner 消费数据、更新策略与价值网络；训练完成后输出可回放或部署的机器人策略。MuJoCoUni 与 MotrixSim 提供 CPU 侧物理后端，统一运行时负责缓冲、主机进程间通信和参数同步，使仿真器、采集器与学习器尽量避免逐步阻塞。策略数据经共享内存缓冲流动，权重则按算法需要同步。

## 训练效率与真机验证

算法的数据依赖也参与调度。PPO 的 on-policy rollout 与更新耦合较强；APPO、FastSAC、FlashSAC 等设置更容易让采样与学习重叠，回放缓冲区可持续供 learner 取样。该系统覆盖人形、四足、灵巧手等机器人控制任务，论文重点验证 simulation-dominated robot control。实验在匹配的单 CPU / 单 GPU 工作站上比较端到端训练效率，并考察跨平台执行。代表性 G1 任务中，Flip 训练加速约 3.3 倍、平地行走约 8.4 倍、动作跟踪约 11 倍；这些数值对应具体算法和任务，并不表示任何仿真配置都能固定提速相同倍数。论文还展示六项仿真训练策略的真机部署任务，作为训练效率结果之外的补充验证。

UniLab 的工程贡献在运行时接口和并行流水线：CPU 物理仿真持续生产交互数据，GPU 执行密集梯度计算，缓冲与异步同步尽量减少空等。任务配置与物理后端、learner 分离后，同一任务可以在支持的仿真后端间切换；运行时仍需显式处理各算法的同步要求与缓冲区使用方式，并非不同后端和算法天然完全等价。它适合需要大批量仿真训练、又希望训练流程不完全依赖 GPU 物理后端的团队。若任务更受视觉渲染、特殊接触求解或单一后端性能限制，实际收益仍需按任务测量；评估时应比较相同硬件和相近策略目标下的端到端时间，而不只看每秒仿真步数。
