# IronLLM：面向端侧的紧凑语言模型

[论文](https://arxiv.org/html/2609.36860) · [IRON 模型家族与官方说明](https://xpeng-robotics.github.io/iron-fm/?model=llm)

机器人在端侧运行语言模型，需要在有限算力和内存中处理较长任务上下文，同时让逐 token 解码足够快，供上层理解、规划和工具调用使用。小鹏机器人基础模型团队提出 654M 参数的 IronLLM，将模型结构、长上下文训练和多 token 解码作为一套端侧部署问题共同设计；它负责语言推理与接口调用，不是直接输出关节动作的 VLA 控制器。

## 混合注意力与多步解码

主体网络共 24 层，按 Gated DeltaNet 与标准全局注意力 3:1 排列，即 18 层线性注意力和 6 层全局注意力。长程信息主要由较低开销的 Gated DeltaNet 处理，穿插的全局注意力保留跨位置交互；相较于每层都使用完整注意力，这种布置降低 KV cache 占用，使模型更适合设备侧长上下文推理。Light 变体进一步以 Dynamic Tanh 替换 RMSNorm，并使用有界 ReLUx 和与数据无关的门控结构，减少量化部署中不友好的运算路径。

解码端的 X-MTP 在共享注意力 KV 的条件下并行提出多个后续 token，由轻量验证头判断草稿是否接受，避免每个预测深度重复回放 KV cache。模型训练则覆盖完整语言栈：研究团队从约 20T token 的候选语料中筛选 6.2T token，预训练分为 4.2T、1T、1T 三阶段，逐步从广泛文本转向数学、代码和推理密集数据；随后把上下文由 4K 延长到 32K 和 64K，并用通用指令微调、数学/代码等专项训练及多域在策略蒸馏构成后训练。

论文报告的指令遵循、知识、数学和工具调用结果分别为 IFEval 75.6、MMLU-Pro 42.1、GSM8K 78.6、BFCL v3 49.4。推理测试使用 RTX 4090、vLLM 0.17.1、BF16、batch 1；在 32K 上下文下，IronLLM 报告 377 token/s，对比 Qwen3 为 166 token/s。X-MTP 相对基准解码方式的加速为 1.48 倍。上述数字对应论文列出的模型、推理栈和测试条件，体现的是端侧语言服务与解码效率，不是机器人闭环成功率。

## 训练流程与推理评测

长上下文结果对应模型经过专门的中训练，而不是仅凭 64K 的位置编码外推：阶段式 RoPE 调整把窗口从 4K 延至 32K、再到 64K，并按长度分桶采样，同时保留接近预训练末期的数据混合，以维持短上下文能力。系统测得 1K 上下文约 460 token/s、32K 约 377 token/s；速度统计在同一 RTX 4090 与推理服务条件下，以三个提示的中位数报告。论文同时给出基础模型、通用指令版本和 Light 变体，分别对应表征能力、语言任务与更紧凑端侧推理需求。
