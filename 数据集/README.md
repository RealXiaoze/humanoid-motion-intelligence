# 具身智能数据集

> 这一页回答：人体动作、人类视频、遥操作、仿真轨迹、数字资产和真机日志分别能训练什么，它们与目标机器人本体之间还隔着哪些转换。

数据集是动作入口、运动基座、LocoManip、VLA和世界模型共同依赖的基础设施。本模块不按论文重复建表，也不把名称相似、平台镜像或单任务小样本直接视为新的正式数据集；所有条目继续由`datasets.csv`维护，并使用稳定的`Dxxx`编号。

## 先分清四种对象

| 对象 | 核心产物 | 不能直接推断什么 |
|---|---|---|
| 原始数据集 | 同一采集协议下的观测、状态、动作、任务和结果 | 数据量大不等于时间同步、动作质量或任务覆盖可靠 |
| 训练数据配方 | 多个数据源经过筛选、转换和采样后组成的预训练或后训练混合 | 配方页面的许可不能替代每个上游数据源的条款 |
| 策略Rollout与失败日志 | 策略执行轨迹、成功失败、接管、重置和恢复过程 | 不能与人类成功示范混在一起统计或训练而不标注来源 |
| 仿真资产库 | 机器人、关节物体、场景、材质、碰撞体和物理参数 | 资产可以生成轨迹，但资产本身不是状态—动作示范 |

## 按训练链路查找

```text
人体动作 / 人类视频 / 遥操作 / 仿真资产
                    ↓
          清洗、标定、同步与动作转换
                    ↓
       目标本体的观测—状态—动作轨迹
                    ↓
        预训练 / 模仿学习 / RL / VLA
                    ↓
                真机执行
                    ↓
       成功、失败、接管、重置与恢复日志
                    ↓
             后训练与再次部署
```

| 数据作用 | 典型内容 | 代表入口 |
|---|---|---|
| 人体动作与语言 | MoCap、SMPL/SMPL-X、文本动作对、全局根节点轨迹和人-物交互动作 | `D001` AMASS、`D009` LaFAN1、`D023` OMOMO |
| 人类视频与Ego数据 | 第一视角/第三视角视频、人体与物体轨迹、音频和任务语义 | `D007` Ego-Exo4D、`D010` Humanoid-X、`D036` Open-AoE-2000H |
| 重定向后的人形动作 | 目标本体根节点、关节参考、接触标签、物理筛选和运动学约束 | `D011` PHUMA、`D031` LAFAN1 Retargeting Dataset |
| 真实机器人示范 | 相机、本体状态、动作、语言、触觉和任务结果 | `D012` Open X-Embodiment、`D024` Humanoid Everyday |
| 仿真合成轨迹 | 不同本体和任务的状态—动作序列、场景与物体状态 | `D021` MimicGen、`D025` GRAIL、`D030` GR00T X-Embodiment Sim |
| 交互物体与数字资产 | USD资产、关节结构、碰撞体、材质、物理参数和可供性 | `D032` ArtVIP |
| 跨本体训练混合 | 数据转换规则、采样比例、统一格式和训练阶段 | `D028` MolmoAct、`D029` MolmoAct2、`D033` ARIO |
| 感知、定位与状态估计 | RGB、深度、LiDAR、IMU、本体状态、标定和同步 | `D034` GrandTour |

完整字段和原始入口见[数据集主表](数据集主表.md)。

## 重点数据链路案例

- [RealOmni-Open：从简智采集设备到数据下载与云端训练](RealOmni-Open.md)：区分数据发布方、采集设备、MCAP记录、解析工具和百度百舸、Hugging Face、ModelScope等分发入口，并说明这类人类双手示范进入目标机器人训练前还缺少哪些转换。
- [Open-AoE：从普通手机采集到机器人模型训练](Open-AoE.md)：解释消费级手机视频怎样经过质量控制、相机与MANO手部恢复、原子动作切分、跨本体重定向和模型专用转换，进入VLA、WAM与世界模型训练。

两者都属于非目标本体的人类操作数据，但不能只按时长比较。Open-AoE以普通手机降低分布式采集门槛，并开放从视频到模型的转换工具；RealOmni-Open使用专用双手采集设备，直接记录IMU、末端位姿和夹爪状态，部分批次还包括深度或触觉。两条路线最终都需要目标机器人动作映射、后训练和真机闭环验证。

## 怎样判断本体依赖

本体依赖不只是“数据来自哪台机器人”。至少要继续检查：动作空间是关节位置、速度、力矩、末端位姿还是动作块；关节顺序、零位、频率、夹爪和控制模式是否一致；相机与本体坐标是否标定；不同模态是否在同一时钟；接触、失败和人工接管是否有记录。

人体视频和MoCap通常需要恢复、重定向与物理化；跨机器人数据需要统一字段后再为目标本体建立动作映射；仿真轨迹还要检查资产、接触和控制器与真机的差异。只有完成这些转换，数据才可能进入目标机器人的训练闭环。

## 数据卡应该检查什么

| 检查项 | 需要回答的问题 |
|---|---|
| 来源 | 人体、真机遥操作、真机自主运行、仿真、生成模型还是混合来源？ |
| 动作表示 | 关节位置/速度/力矩、末端位姿、人体参数、轨迹还是动作块？ |
| 时间与回合 | 相机、状态、动作和力触觉是否同步？回合、重置与缺帧怎样记录？ |
| 结果覆盖 | 是否包含失败、接管、恢复、奖励、成功条件和终止原因？ |
| 本体与控制 | 机器人型号、自由度、关节映射、控制频率和控制模式是否公开？ |
| 许可分层 | 数据、视频、3D资产、代码和模型权重是否分别允许商用、修改和再分发？ |
| 下游证据 | 数据是否实际进入训练、评测或真机部署，而不只是提供下载？ |

先看许可和可追溯性，再看坐标、动作、接触与时间质量，最后才看规模。

## 世界模型需要什么数据

世界模型数据不能只有视频和动作两列。一条可用于后果预测、动作验证或真实反馈更新的记录，至少应尽量保留：

```text
当前环境观测 + 机器人状态 + 执行动作
                         ↓
后续环境观测 + 机器人后续状态 + 物体与接触变化
                         ↓
任务进度、成功/失败、风险、人工接管、重置与恢复
```

所有信号还需要统一时间轴、回合边界、坐标与本体定义。缺少动作条件的数据可以学习场景和动态先验，但不能直接证明模型学会了“执行动作A或动作B会分别发生什么”；只有成功示范的数据也不足以训练可靠的风险判断和失败恢复。

按用途还应区分三类数据：

- **预测训练数据**：连续观测、状态、动作和结果完整对齐，用于学习未来变化；
- **决策与验证数据**：同一状态下包含多个候选动作、策略Rollout或成功失败对照，用于排序、奖励和风险模型；
- **受控更新数据**：保留模型版本、部署条件、失败类型、人工处理和复测结果，用于真实反馈闭环与回归验证。

## 代表条目的分类边界

- `D028-D029`区分MolmoAct的原始示范、Action Reasoning训练混合、MolmoAct2跨本体训练集合和策略Rollout，避免把“数据集”“训练配方”和“失败评测轨迹”写成同一种数据。
- `D030`记录NVIDIA用于GR00T后训练的跨本体仿真操作轨迹，并保留不同本体动作空间不能直接互换的边界。
- `D031`记录社区版LAFAN1人形重定向轨迹。它只处理运动学约束，且上游许可限制严格，因此状态标为`watch`。
- `D032`将ArtVIP归为交互物体和数字孪生资产，而不是机器人示范数据。
- `D033`记录ARIO统一格式及真实、仿真、开源转换三类来源，许可保持`MIXED`。
- `D034`补充ANYmal多传感器数据，用于状态估计、定位和复杂环境感知，不把它误写成Locomotion动作模仿数据。
- `D035`记录简智机器人发布的RealOmni真实家庭双手操作数据。数据带有末端位姿和夹爪状态，但不包含特定目标机器人的关节与低层控制闭环，因此归为非目标本体人类示范，而不是可直接部署的机器人轨迹。
- `D036`记录Open-AoE手机第一视角操作数据。MANO手部、相机轨迹和原子动作提高了视频的可转换性，但仍不等于目标机器人关节、力矩或控制器状态；公开工具链与数据、模型和第三方资产的许可也需要分开核对。
- `D038`记录它石智航World In Your Hands人类中心操作数据。Oracle Suite同步采集视觉、手部动作和部分触觉，自动标注与人工复核生成跨模态监督；各模态覆盖时长不同，数据生态也不等于AWE 3.0模型权重已经开放。

## 使用边界

- 中国信通院鲸智社区等聚合平台只作为候选发现入口；正式记录优先链接原作者项目页、数据卡或机构仓库。
- 同一数据的镜像、转换版和训练混合先判断是否具有独立数据结构、许可或下游用途，再决定是否新增编号。
- 小型LeRobot单任务数据可以用于格式验证和冒烟测试，默认不逐条占用正式`Dxxx`编号。
- 仓库只记录公开数据卡能够支持的字段；未披露的同步精度、失败比例、动作含义和商用权利统一保持未知。
