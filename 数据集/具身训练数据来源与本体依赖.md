# 具身训练数据来源与本体依赖

具身训练数据不能只按“有多少小时”比较。真正决定数据能否进入机器人训练的，是它记录了什么观测、用什么动作表示、与哪种本体和控制接口绑定，以及缺失的信息能否通过重建、重定向或少量真机数据补上。人类视频、遥操作、仿真和真实日志各自解决不同问题，没有一种来源能够自动替代其他来源。

## 四类数据分别提供什么

| 数据来源 | 直接提供 | 通常缺少 | 最适合解决的问题 |
|---|---|---|---|
| 真实机器人遥操作与运行日志 | 相机、本体状态、机器人动作、任务结果和真实接触后果 | 规模、任务覆盖与跨本体通用性 | 闭环策略训练、真机后训练、失败恢复与部署验证 |
| 仿真与合成数据 | 完整状态、接触、力、场景真值和可批量生成的动作 | 真实传感器误差、执行器差异和复杂材料接触 | 预训练、强化学习、边界场景和自动化评测 |
| 第一人称人类视频 | 真实场景、物体变化、操作语义、手腕或手部运动 | 机器人关节动作、本体感觉、控制频率、力与执行器状态 | 视觉表示、任务结构、手物交互和动作先验预训练 |
| MoCap、可穿戴设备与UMI | 人体或末端的三维轨迹，部分系统同时记录视觉和按键 | 目标机器人动作、动力学可行性和本体特有接触 | 动作恢复、重定向、跨场景示范采集 |

真实机器人数据离部署最近，但昂贵并且强本体绑定；仿真数据便宜且状态完整，却需要处理Sim2Real；人类视频规模大、场景真实，却没有可直接下发给机器人的动作；UMI和可穿戴系统处于两者之间，能够保留更明确的操作轨迹，但仍要经过标定、动作映射和机器人闭环验证。

## “本体依赖”具体依赖什么

本体依赖不只是机械臂型号不同。至少有六层差异会决定一条数据能否复用：

1. **观测依赖**：相机位置、视野、深度、触觉、IMU和关节编码器不同，同一个任务在不同机器人上看到的信息并不一样；
2. **动作依赖**：数据可能记录关节位置、关节速度、力矩、末端位姿、夹爪开合、动作块或技能指令，不能在未定义转换时混为同一监督；
3. **运动学依赖**：自由度、连杆长度、关节限位、工作空间和末端结构决定人的手轨迹能否映射到机器人；
4. **动力学与接触依赖**：质量、惯量、摩擦、执行器能力、柔顺性和手指接触决定几何上相似的动作能否真实完成；
5. **时序与控制依赖**：相机帧率、策略频率、通信延迟、低层伺服和动作执行时间共同决定动作序列的物理含义；
6. **部署依赖**：模型导出、关节顺序、坐标系、安全约束和故障恢复必须适配具体机器人，离线指标不能替代这一步。

因此“跨本体数据”通常不是删除机器人ID后直接混合，而是先寻找可以共享的中间表示，例如世界坐标下的手腕轨迹、物体位姿变化、MANO手部姿态、末端目标或离散动作槽位，再用本体专属映射和少量真机数据补足剩余差异。

## 人类视频怎样进入机器人训练

一条可执行的数据链通常经过以下步骤：

**原始视频与任务文本 → 相机和时间处理 → 人手、人体与物体恢复 → 片段切分与质量筛选 → 中间动作表示 → 目标本体映射 → 机器人后训练 → 真机闭环验证。**

相机和时间处理负责去畸变、估计相机运动并把不同帧对到同一几何参考；人体和物体恢复把像素变化转成手腕、手指、物体或身体的可跟踪状态；片段切分将长视频变成有起止边界的原子操作，并剔除跟踪失败或语义不清的样本。中间动作表示是整条链的关键：它既要比特定机器人关节更容易跨本体共享，又要保留足够的方向、接触和时序信息，不能只剩一句任务文本。

目标本体映射随后把手部或末端轨迹变成机器人可达的关节、末端目标或动作槽位，并检查限位、碰撞、接触和动力学可行性。机器人后训练使用较少但带真实本体状态和动作的数据，让模型学会具体相机、执行器和控制接口。最终仍要在闭环中检查误差是否累积、接触是否成功以及失败后能否恢复。人类视频能够扩大预训练覆盖，但不能单独证明机器人已经获得可部署动作。

| 工作 | 数据怎样进入 | 形成的中间表示或策略 | 不能据此推断什么 |

| [Being-H0.5](../论文与项目/论文逐篇解读/P166.md) | 人类、机器人与视觉语言数据混合 | 用物理可解释动作槽位统一手、末端、关节和移动底座，再做本体适配 | 统一槽位没有消除各本体的动力学与部署差异 |
| [VITRA](../论文与项目/论文逐篇解读/P167.md) | 多个第一人称视频集经相机、手部与轨迹处理 | 生成带指令和未来手部轨迹的大规模预训练片段 | 数据量不等于所有片段都能直接转成机器人示范 |

| [GEN-0](../论文与项目/论文逐篇解读/P172.md) | 公司自建的大规模真实物理交互数据 | 跨多种机器人预训练同一具身基础模型 | 公司报告的数据规模和Scaling结论尚不能替代公开数据、代码与同行评审 |

## 从数据来源到训练配方

[Data Pyramid for Embodied Manipulation](../论文与项目/论文逐篇解读/P207.md)从数据可扩展性与机器人任务对齐程度讨论五层数据生态，适合补充“不同来源在预训练与后训练中各承担什么作用”。它是综述与资源索引，不是新发布的数据集；本页的四类来源是工程采集视角，不能与综述层级机械地一一对应。

模型报告中的总小时数也不是可直接下载的数据目录。至少应区分原始采集时长、清洗后的有效片段、采样或重复使用量、训练阶段混合比例，以及实际向开发者开放的部分。

| 案例 | 适合追踪的数据问题 | 阅读边界 |
|---|---|---|
| [OpenWAM](../论文与项目/论文逐篇解读/P194.md) | 在相对统一的数据和训练框架下比较视觉编码、动作表示和联合建模选择 | 6369小时是混合训练规模；各来源、处理脚本、模型与许可需要分别核对 |
| [GE-Act 2.0](../论文与项目/论文逐篇解读/P195.md) | 视频与动作联合训练扩大后，哪些目标本体和分布外任务得到增益 | 编码器、视觉预测、逆动力学和联合训练阶段可能复用数据，不应将各阶段小时数直接相加 |
| [ZimaBlue](../论文与项目/论文逐篇解读/P196.md) | 人类与机器人视频如何经视频预训练、异构动作中期训练和目标机器人后训练进入控制 | 12万小时视频不等于12万小时带机器人动作标签的示范，也不等于该规模的数据已经公开下载 |
| [Motus2](../论文与项目/论文逐篇解读/P197.md) | 成功示范与策略生成轨迹如何分别服务策略、模拟器和评估器 | 离线候选动作评分不等于更新参数；模型强化学习阶段的数据与监督必须单独记录 |

采集工具还要检查字段的实际语义。例如[FluxVLA的Oli采集文档](https://github.com/FluxVLA/FluxVLA/blob/main/docs/oli_whole_body.md)中，手部状态来自上一条开合命令的回显，并非测得的手指状态；图像与关节采用最新样本读取，不意味着已经完成时间戳同步。把文件转换为LeRobot格式，只解决了存储和读取接口，不能自动补足真实反馈、同步误差或失败标签。

以上模型先进入论文与项目记录；只有存在独立、可核验的数据卡和访问范围时，才在[数据集总览](README.md)建立或更新数据集条目。训练混合配方与原始数据集通过链接关联，避免同一批数据被重复统计。

## 现阶段可以成立的判断

“大规模非目标本体数据预训练，再用较少目标机器人数据后训练”已经有多项研究和公司报告支持，值得作为数据系统的设计方向。但它还不是对所有任务都已验证的固定主流范式。精密插装、强接触、灵巧手、双足全身操作和高安全要求任务，对触觉、力、本体状态与闭环恢复的依赖不同，所需真机数据比例也不会相同。

判断一套数据方案是否有效，应继续追问：原始数据如何同步和清洗，中间动作表示保留了什么，跨本体映射在哪里发生，目标机器人数据承担什么监督，训练与测试是否按场景和任务隔离，以及最终是否在真实闭环中提高成功率、恢复能力和稳定性。只比较总时长，无法回答这些问题。

## 数据选用与检查

### 先分清四种对象

| 对象 | 核心产物 | 不能直接推断什么 |
|---|---|---|
| 原始数据集 | 同一采集协议下的观测、状态、动作、任务和结果 | 数据量大不等于时间同步、动作质量或任务覆盖可靠 |
| 训练数据配方 | 多个数据源经过筛选、转换和采样后组成的预训练或后训练混合 | 配方页面的许可不能替代每个上游数据源的条款 |
| 策略Rollout与失败日志 | 策略执行轨迹、成功失败、接管、重置和恢复过程 | 不能与人类成功示范混在一起统计或训练而不标注来源 |
| 仿真资产库 | 机器人、关节物体、场景、材质、碰撞体和物理参数 | 资产可以生成轨迹，但资产本身不是状态—动作示范 |


### 数据卡应该检查什么

| 检查项 | 需要回答的问题 |
|---|---|
| 来源 | 人体、真机遥操作、真机自主运行、仿真、生成模型还是混合来源？ |
| 动作表示 | 关节位置/速度/力矩、末端位姿、人体参数、轨迹还是动作块？ |
| 时间与回合 | 相机、状态、动作和力触觉是否同步？回合、重置与缺帧怎样记录？ |
| 结果覆盖 | 是否包含失败、接管、恢复、奖励、成功条件和终止原因？ |
| 本体与控制 | 机器人型号、自由度、关节映射、控制频率和控制模式是否公开？ |
| 许可分层 | 数据、视频、3D资产、代码和模型权重是否分别允许商用、修改和再分发？ |
| 下游证据 | 数据是否实际进入训练、评测或真机部署，而不只是提供下载？ |

先看许可和可追溯性，再看坐标、动作、接触与时间质量，最后才看规模。


### 世界模型需要什么数据

世界模型数据不能只有视频和动作两列。一条可用于后果预测、动作验证或真实反馈更新的记录，至少应尽量保留：

```text
当前环境观测 + 机器人状态 + 执行动作
                         ↓
后续环境观测 + 机器人后续状态 + 物体与接触变化
                         ↓
任务进度、成功/失败、风险、人工接管、重置与恢复
```

所有信号还需要统一时间轴、回合边界、坐标与本体定义。缺少动作条件的数据可以学习场景和动态先验，但不能直接证明模型学会了“执行动作A或动作B会分别发生什么”；只有成功示范的数据也不足以训练可靠的风险判断和失败恢复。

按用途还应区分三类数据：

- **预测训练数据**：连续观测、状态、动作和结果完整对齐，用于学习未来变化；
- **决策与验证数据**：同一状态下包含多个候选动作、策略Rollout或成功失败对照，用于排序、奖励和风险模型；
- **受控更新数据**：保留模型版本、部署条件、失败类型、人工处理和复测结果，用于真实反馈闭环与回归验证。
