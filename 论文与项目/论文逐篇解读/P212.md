# FluxVLA Engine：把策略实验接到真机闭环的工程平台

> 对应本库已有开源项目 R208；技术报告提供系统边界与实验口径，不需要再建一个同名项目。

FluxVLA Engine 的主张不是提出新的策略模型，而是用配置驱动的统一接口串接异构数据、VLA/WAM/离线强化学习策略、分布式训练、仿真评测、推理服务和真机操作。模型原生实现、集成实现和机器人部署三者应分别核对，不能因平台能加载某个模型，就认为完整复现了它的论文配方。

## 数据到执行的接口

```text
异构机器人数据 → 统一转换与配置 → 策略训练/后训练
                                     ↓
                               仿真及离线评测
                                     ↓
相机/本体观测 → 策略 predict_action → 动作块/RTC → 轨迹后处理 → 机器人
      ↑                                                        ↓
      └──────────── 真机执行、接管、纠错与奖励标注 ──────────────┘
```

报告还覆盖双臂仿真任务组合、自动生成数据、人工接管与纠错、远程 GPU 推理、轨迹平滑等组件。它们解决的是工程契约和闭环复现问题：数据标准化是否保留相机、动作和时间同步；仿真评测能否和真机观察对齐；推理加速是否改变动作数值；动作块交接、后处理与网络延迟会否改变实际控制行为。

## 报告中的证据怎样读

报告列出八组模型路径加速，范围约 2.31 至 9.64 倍。其中最大值来自 A100 上 π0.5 路径由 2.20 Hz 到 21.2 Hz；这是模型执行频率，不是机器人相机到执行器的端到端控制频率。不同设备和模型采用不同优化路径，原始计时轨迹及统一的预热、同步、输入形状等协议仍不完整，因此不能把最大值当作所有模型/硬件配置的收益。

真机部分让 GR00T N1.5 和 π0.5 走同一 ALOHA 部署路径，每个策略在五项任务中合计测试 110 次，分别成功 36/110 与 70/110。它证明平台确实连接到物理执行，也为检查部署接口提供了案例；两个策略的预训练、后训练和数据预算不同，不能据此断言平台使 π0.5 优于 GR00T，或使任一模型相对原生部署提高了多少。报告的 RoboCasa 多模型结果同样不是匹配初始化、数据量和优化预算的受控架构排行榜。

## 与已有记录的关系

已有的 [FluxVLA Engine 项目记录](../开源项目主表.md)负责入口、代码开放范围和版本跟踪；本页负责方法、证据和适用边界。开发者若要采用平台，建议以一套固定数据、相同观测/动作定义和相同策略检查点做三段验收：数据转换前后对齐、仿真与真机动作数值/时序一致性、端到端任务成功及故障恢复。RTC 和轨迹后处理可以缓解动作块交接问题，但不自动提供碰撞安全、力控稳定性或不同本体的零配置移植。
